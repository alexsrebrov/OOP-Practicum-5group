# Множествено наследяване. Виртуално наследяване. Диамантен проблем.

## Множествено наследяване

Един клас може да бъде **наследник на повече от един клас**

```c++
class A {...}
class B {...}

class C : public A, public B {...}

void f(A& obj);
void g(B* ptr);

int main() {
    C c;
    f(c);
    g(&c);
    // obj/ptr могат да се ориентират към коя част на C да сочи, независимо от подредбата
}
```

![](/Week14/resources/multiple_inheritance.png)

От значение е **подредбата на наследяване** за конструктор/деструктор/копиране (компилатора се грижи сам тя да бъде спазена):

```c++
class C : public A, public B {
    C() : B(), A()
    // независимо как сме подредили класовете в инициализиращия списък, първо ще се създаде A и после B, понеже така сме ги наредили при наследяването
}
```

При `operator=` обаче, понеже това е оператор, а не конструктор, компилатора не може да следи за изпълнение на подредбата при наследяване - трябва ние сами да извикаме в правилен ред `operator=` на базовите класове.
```c++
C& operator=(cosnt C& other) {
    if (this != &other) {
        A::operator=(other);
        B::operator=(other);
        free();
    }

    return *this
}
```

## Диамантен проблем
```c++
class A {...}
class B {...}
class C {...}
class D : public B, public C {...}
```

![](/Week14/resources/diamond.png)

Възможно е да имаме такава йерархия, че един клас (`class D`) е налседник на други два класа (`class B` и `class C`), които имат общ родител (`class A`). Получава се т.нар. **диамантен проблем**

![](/Week14/resources/multiple_inheritance_diamond.png)
*(чисто илюстративно, не приемайте, че е така подредено точно така в паметта)*


Въпреки че *A* е отделно спрямо *B* и *C*, за класа *D* то е едно единствено. Съответно при *D()* викаме два пъти конструктора на едно и също *A* заради *B()* и *C()* 

Още по-големият проблем идва при деструктора - при извикване на *~D()* ще извикаме *~A()* два пъти за един и същи обект -> грешка

## Виртуално наследяване
```c++
class A {...}
class B : virtual public A {...}
class C : virtual public A {...}
class D : public B, public C {...}
```

Дори да имаме `B(...) : A(...)` и `C(...) : A(...)` (извикали сме някакви конкретни конструктори на *A*), виртуалното наследяване прави така, че *D* (и като цяло всеки наследник на *B* и *C*) вика default-ен конструктор на *A*

**Съответно ние трябва да извикаме**
```c++
D(...) : A(...), B(...), C(...) 
//конкретния конструктор на A, който ни трябва -> това се свежда до едно създаване на A
```

В някакъв смисъл *A* вече е директен родител на *D* и *D* трябва да се грижи за логиката по наследяването на *A* (а не да очаква *B* и *C* да се погрижат за него)

![](/week14/resources/virtual_inheritance.png)

Въпреки това *B* и *C* все пак имат достъп до *A* -> то е общо и за двете и го достъпват с указатели

**A отива в края на D**

## Виртуални таблици
### множествено наследяване
```c++
class BC1 {
public:
    virtual void f() {...}
    virtual void k() {...}
}

class BC2 {
public:
    virtual void g() {...}
}

class BC3 {
public:
    virtual void f() {...}
    virtual void t() {...}
}

class Der : public BC1, public BC2, public BC3 {
public:
    void f() override {...} // когато няколко от родителите имат едно и също име на метод *задължително* трябва да override-нем
    void g() override {...}
}

int main() {
    Der d;
    BC1* ptr1 = &d;
    BC2* ptr2 = &d;
    BC3* ptr3 = &d;

    ptr1->f() // Def::f()
    ptr2->g() // Der::g()
}
```

![](/Week14/resources/multiple_inheritance_ptr.png)

`ptr2` сочи *BC2*, а не *Der*. Начина, по който компилатора се ориентира е чрез *$\Delta$(<клас>)* - колко е отместването на даден клас от началото на наследника му (т.е. *колко да се мести указателя, че да достигне нужния базов клас*)

$\Delta$(BC1) = 0 -> то е в началото на *Der*, съответно няма отместване

$\Delta$(BC2) = **sizeof(BC1)**

$\Delta$(BC3) = **sizeof(BC1)** + **sizeof(BC2)**

### виртуално наследяване
```c++
class A {
    virtual void f() {...}
    virtual void g() {...}
    virtual void h() {...}
    virtual void t() {...}
}

class B : virtual public A {
    void f() override {...}
}

class C : virtual public A {
    void g() override {...}
}

class D : public B, public C {
    void t() override {...}
}

int main() {
    D d;

    A* ptr = &d;
    // B::f(), C::g(), D::t(), A::h()
}
```

![](/week14/resources/virtual_inheritance_ptr.png)

| Функция | отместване на ptr | коментари |
| --- | --- | --- |
| B::f() | -$\Delta$(A) | *B е в началото на D и трябва да се върнем там* |
| C::g() | -$\Delta$(A) + $\Delta$(C) |  |
| A::h() | 0 | *ptr сочи частта на A; няма какво да местим* |
| D::t() | -$\Delta$(A) | *трябва да сочим цялото D, т.е. да се върнем в началото на D; в случая B е в началото на D, затова делта фунцкиите им съвпадат* |


При `B* ptr2 = &d`:

| Функция | отместване на ptr |
| --- | --- |
| B::f() | 0 |
| C::g() | $\Delta$(C) |
| A::h() | $\Delta$(A) |
| D::t() | 0 |
