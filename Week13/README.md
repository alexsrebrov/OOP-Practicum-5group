# Ламбди и std::function

**Ламбите** са малки функции, които нямат име и могат да бъдат написани директно на място, където очакваме да бъде подаден параметър функция. Често намират употреба при кратки функции.

### Синтаксис

```c++
[capture] (parameters) { code };
```

Въпреки че в частта `code` би могло да напишете няколко реда код, разделени с `;`, не е препоръчително да го правите:
* ламбдите са предназначени за кратки операции
* чисто синтактично не е много четимо написано по такъв начин

Другото ключово при ламбдите е, че *нямат име*, именно понеже са предназначени да бъдат използвани на *едно* място в програмата за извършването на бърза операция. Ако ще повтаряте периодично една и съща операция, зададена с ламбда, по-добре я изнесете в нормална функция.

Пример:
```c++
#include <iostream>
#include <functional> // За да може да използваме function<>

void myFunc(function<void(string)> func) { func("Alex!"); }

int main() {
    string output = "Hello, ";
    string name = "Mitko!";

    function<void(string)> message1 = [output](string name) {
        cout << output << name << '\n';
    };

    auto message2 = [output](string name) {
        cout << output << name << '\n';
    };
    
    void (*message3)(string, string) =
        [](string output, string name) {
            cout << output << name << '\n';
        }; // Cannot have capture

    message1(name);             // Hello, Mitko!
    message2(name);             // Hello, Mitko!
    message3(output, name);     // Hello, Mitko!
    myFunc(message1);           // Hello, Alex!
    myFunc(([output](string name) 
    { cout << output << name << '\n'; })); // Hello, Alex!

    return 0;
}
```

#### Как работи capture?
Има три начина по които може да capture-нем:
 - *по референция*
 - *по стойност*
 - *и по двете*

```c++
// capture by reference
int main() {
    vector<int> vec = {10, 20, 30, 40, 50};

    auto lambda = [&vec]() {
        for (int& num : vec) {
            num *= 10;
        }
    };
    lambda();

    for (int num : vec) {
        cout << num << " ";
    } // Output [ 100, 200, 300, 400, 500 ]

    return 0;
}
```

```c++
// capture by value
int main() {
    vector<int> vec = {10, 20, 30, 40, 50};

    auto lambda = [vec]() {
        for (int num : vec) { // Cannot get int& num, because is const int
            cout << (num *= 10) << " ";
        }
    };
    lambda();  // Output [ 100, 200, 300, 400, 500 ]

    for (int num : vec) {
        cout << num << " ";
    } // Output [ 10, 20, 30, 40, 50 ]

    return 0;
}
```

```c++
int main() {
    vector<int> vec1 = {10, 20, 30, 40, 50};
    vector<int> vec2 = {1, 2, 3, 4, 5};

    auto lambda = [&vec1, vec2]() {
        for (int& num : vec1) {
            num *= 10;
        }
        for (int num : vec2) {
            cout << num * 10 << " ";
        }
        cout << endl;
    };

    lambda(); // Output [ 10, 20, 30, 40, 50 ]

    cout << "Vector 1: ";
    for (int num : vec1) cout << num << " "; // Output [ 100, 200, 300, 400, 500 ]

    cout << "\nVector 2: ";
    for (int num : vec2) cout << num << " "; // Output [ 1, 2, 3, 4, 5 ]

    return 0;
}
```

## Малко повече за std::function
Както помните от УП, фунцкиите, като всяко друго нещо в програмта, трябва да бъдат запазени по някакъв начин в паметта. Щом се запазват в паметта, то значи те имат адрес, *значи и могат да бъдат достъпени чрез указател*.

Именно указателите към фунцкии ни помагат да реализираме т.нар *функции от по-висок ред* - функция, която приема като параметър друга функция (така това е фунцкия, която няма едно единствено поведение).

Пример:
```c++
int square(int x) {
	return x * x;
}

int cube(int x) {
	return x * x * x;
}

int sum(int (*quantifier)(int), int n) {
	int res = 0;
	for (int i = 1; i <= n; i++) {
		res += quantifier(i);
	}

	return res;
}


int main()
{
	std::cout << sum(square, 4) << std::endl;
	std::cout << sum(cube, 5);

	return 0;
}
```

# Изключения
Механизъм за обработка на грешки, възникнали по време на изпълнение на програмата.

Позволяват отделяне на обработването на грешката от основната логика на програмата.

```c++
throw <обект, показващ грешка>

...

try
{
    // парче код, което би могло да хвърли грешка
} catch(<обект, показващ грешка>)
{
    // логика по хванащането на грешката
}
```

Видове грешки:
* **char** -> *throw 's'*
* **int** -> *throw 3*
* **double** -> *throw 3.14*
* **std::exception** - има редица наследници, сигнализиращи различни грешки
    * *std::bad_alloc* - грешка при заделяне на памет
    * *std::runtime_error* - грешка по време на изпълнение
    * *std::logic_error*
    * *std::terminate* - автоматично приключва програмата
    * ...и още много...

    Опитвайте се да хвърляте грешка спрямо конкретната грешка, която сте получили - цялата идея на exception-ите е да сигнализират, че има проблем, **но и да укажат точно какъв е проблема**. Въпреки това има случай, в които не е напълно еднозначен вида на грешката.

    #### std::terminate
    Програмата не може да обработи едновременно две грешки. Ако се получи ситуация, в която имаме две грешки едновременно, компилатора хвърля автоматично *std::terminate*, т.е. програмата приключва.

### Stack Unwinding

```c++
class A { 
    // ...някаква реализация... 
}

class B { 
    // ...някаква реализация... 
}

void g() {
    throw ...
}

void f() 
{
    A a; // A(), създаваме обект от тип B
    B b; // B(), създаваме обект от тип B

    g(); // хвърляме грешка -> при хвърляне на грешка stack-а се изпразва -> съответно извикваме деструкторите ~B() и ~A()
}
```

### Хвърляне в конструктори
При *stack-unwinding* се викат деструктори *само на напълно създадени обекти* (иначе нямаме готов обект, чийто деструктор да извикаме) 

Ако хвърлим грешка в конструктор, т.е. обекта е частично създаден, деструктор няма да се извика. **В такъв случай, ако ние сме заделили ръчно някаква памет, трябва ние ръчно да я зачистим.**

```c++
class X
{
    A obj1;
    B obj2;

public:
    X(A obj1, B obj2) : obj1(obj1), obj2(obj2)
    // ако при конструирането на obj2 хвърлим грешка, то единствено ~A() ще бъде извикано, понеже то е единствения напълно създаден обект
}
```

### Хвърляне в деструктори
Нормалното извикване на деструктор е вид своеобразен *stack-unwinding* (обаче контролиран само за един обект). Съответно ако хвърлим грешка ще се задейства още един *stack-unwinding*, което води до `std::terminate`

(донякъде може да се приема, че деструктора ""неявно хвърля изключение"" (но това е с много кавички))

## Йерархия на catch блоковете
Започваме с най-конкретното и отиваме към по-общите

```c++
try
{

}
catch (std::runtime_error)
{

}
catch (std::exception) // хваща std::exception и всички негови наследници
{
    
}
catch (...) // хваща всякакви грешки
{

}
```

Ако бяхме разменили местата `std::runtime_error` и `std::exception`, никога нямаше да влезем в блока на `std::runtime_error`, понеже `std::exception` го хваща

## Exception safety
* ***No throw*** - гарантира, че никога няма да хвърли грешка
* ***Strong exception safety*** - може да хвърли грешка (която хващаме), но гарантираме, че входния обект няма да бъде променен
* ***Weak/Basic exception safety*** - може да хвърли грешка (която хващаме), но *не* гарантираме, че входния обект няма да бъде променен
* ***No guarantee*** - няма защита на грешки
