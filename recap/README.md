# Преговор

## Обектно-ориентирано програмиране
**Програмна парадигма** - представлява фундаменталния стил на програмиране

**Обектно-ориентирано програмиране** е *програмна парадигма*, при която програмата се моделира като набор от обекти, които взаимодействат помежду си.

Всеки обект е способен да получава съобщения (данни), да ги обработва и изпраща съобщения на други обекти.

**Основни принципи на ООП:**

* *енкапсулация*
  * обекта предоставя на потребителя/ползващия го само пряко необходимите му средства за работа, останалата информация държи скрита

* *наследяване*
  * позволява да бъдат дефинирани и създавани обекти, които са специализирани варианти на други, вече съществуващи
  
  * наследникът взема всички свойства и методи на родителя
* *полиморфизъм*
  * позволява обекти от един и същ тип да имат еднакъв интерфейс, но различна интерпретация на този интерфейс
  
  * т.е. едни и същи действия се изпълняват по различен начин в зависимост върху кой обект се прилагат
* *абстракция*
  * скриване на реализацията на даден обект от потребителя и предоставяне само на интерфейс за работа с него
  
  * позволява да се работи с обекти на по-високо ниво, без да е нужно да се знае как точно функционират отвътре


## Class vs Struct
Както стана ясно от предишната точка, в ООП работим с обекти, но как ги реализираме? Ами тук се намесват добре познатите ви **класове и структури**, а обектите са просто тяхна конкретна реализация. Общо и за двете може да се каже:
* използват се за групиране на елементи

* елемнтите се наричат членове (*член-данни*) и могат да бъдат от различен тип
* щом имаме еквивалент на променливите в класовете/структурите е логично да имаме и за функциите: *член-функциите* са функции, които се намират вътре в класа/структурата:
  * работят с техните член-данни

  * извикват се от конкретен обект
  * имат допълнителен параметър, който е *const указател към обекта* (малко повече за това по-надолу)

Класовете и структурите са доста близки, но за да кажем разликата между тях трябва първо да въведем:

### Модификатори за достъп
Модификатора за достъп определя дадена член-данна/функция кой може да я достъпва. Както вече знаете, имаме 3 модификатора:
* **public** - всеки има достъп
* **protected** - само самия клас/структура има достъп + *наследниците му* (за тях повече при наследяване)
* **private** - само самия клас/структура има достъп

Благодарение на модификаторите за достъп можем да реализираме първия ООП принцип - **енкапсулация**
* скриваме определени данни от потребителя, до които не искаме да има достъп
* даваме механизъм за евентуална работа и достъп до тези скрити данни - добре познатите ви *getter-и и setter-и*

В крайна сметка да се върнем на там, откъдето започнахме: разликата между клас и структура е, че при **класовете всичко е private**, докато при **структурите всичко е public**

**¡Важна препоръка!** - Въпреки че не е непременно правило, почти навсякъде се приема, че структурите се използват само за малки обекти/елементи, а класовете са за по-големи

Напр., ако искаме да моделираме точка от равнината, която има само координати, ще я направим структура, защото няма други функционалности
```c++
struct Point {
    double x;
    double y;
};
```

Но ако искаме и да имаме обект, който да извършва линейни трансформации върху дадената точка, това вече е нещо, което ще е клас.

Оттук нататък за простота на пишещия и на четащия ще използваме само класове, но може да приемете, че нещата са напълно еквивалентни и за структури

### Малко повече за член-функциите
Както стана ясно от определението, класовете са начин за обединяване на няколко елемента (променливи) в едно. Силното обаче е, че не само пазим тези член-данни, но и можем да извършваме операции с тях вътре в обекта - това става благодарение на *член-функциите*

```c++
class A {
    int a;
public:
    A(int a) : a(a) {}

    void f() {
        return a + 1;
    }
}

int main() {
    A a1(4);
    A a2(5);
    A a3(6);

    std::cout << a1.f() << " " << a2.f() << " " << a3.f(); // 5 6 7
}
```

Горния пример ще изведе *5 6 7* на конзолата - как обаче обектите знаят кое `a` да използват - нали всички те са разлизация на един и същи клас? Тук се намесва начина, по който са реализирани член-методите, и по скоро указателя this

***Указателя this*** е **константен** указател, който сочи към конкретния обект. Той присъства във всеки един член-метод и затова дори няма нужда да се пише в списъка с аргументи - *въпреки това е там и винаги е първи параметър*.

В горния пример, ако трябва да го разпишем експлицитно:

```c++
class A {
    int a;
public:
    A(int a) : a(a) {}

    void f(A const* this) { // за компилатора изглежда така, но не ни го показва
        return a + 1;
    }
}
```

### Константни член-функции
Едно нещо, което ще се стремим да правим, е да *спазваме **const correctness***, т.е. когато няма да правим промени да означаваме обекта/действеито с const. Съответно, за да постигнем това, можем да означим дадени член-фунцкии като *константни*.
* не променят член-данните
* пише се `const` в края на декларацията
* конст. обекти могат да викат само конст. член-функции
* в тялото на конст. член-фунцкии *не може* да се викат не-конст. член-функции

```c++
class A {
    void f() {} // еквивалентно на void f(A const* this

    void g() const // еквивалентно на void g(const A const* this
}

```

## Жизнен цикъл на обект
Разбрахме какво са класовете и структурите и че обектите са тяхна конкретна реализация. Как обаче ги реализираме? ***Жизнения цикъл на обект*** е:
1. Създаване на обект в даден scope - заделя се памет
2. Работим с обекта
3. Стигаме до края на scope-а

4. Заделената памет за обекта се освобождава, обекта се изтрива

### Конструктор
**Конструкторът** е специален вид член-метод, който:
* извиква се само веднъж - *при създаването на обекта*

* не се оказва експлицитно тип на връщане (връща конст. референция към новосъздадения обект)
* има същото име като класа
* присвоява стойности на член-данните (в тялото или инициализиращ списък) - *създава обекта*
* **може да се overload-ва**, тоест можем да имаме няколко конструктора

```c++
class C {
    A a;
    B b;

public:
    C(int i, double d) : b(d), a(i) {}
}
```

В горния пример е показан **инициализиращ списък (initializer list)**. Той ни позволява да извикаме конкретния конструктор за член-данната, която ни трябва (т.е. *да окажем конкретния начин, по който искаме да я инициализираме*). Ако не окажем нищо в инициализиращия списък се вика default-ен конструктор на дадената член-данна.

**Реда в инициализиращия списък не е от значение!!! Следва се реда, по който сме подредили член-данните в класа** (в случая - създава се първо `A`, после `B`)

Това се дължи на начина, по който `C` се пази в паметта, а именно:

![](/recap/resources/c.png)

Някои типове/по-специални конструктори
* **конструктор без параметри** -> *default-ен*/*конструктор по подразбиране*
  * ако ние сами не сме разписали никакви други конструктори, програмата сама създава такъв
  * в противен случай се ползва създадения от нас и губим default-ния (освен ако не го разпишем сами експлицитно)
  * **ако имаме масив от обекти автоматично се извиква default-ния конструктор**

* **конвертиращ конструктор** -> конструктор с *точно 1* параметър
  * можем да създаваме неявно един обект
    ```c++
    class A{
        A(int a) {...};
    }

    int main() {
        A a = 10; // еквивалентно на A a(10);
    }
    ```
  * компилатора сам се ориентира как да третира подадения параметър като цял обект от дадения клас - оттук идва и името, *"конвертираме" параметъра в обект от класа* (в случая 10 "конвертираме" в `A`)

### Деструктор
Специална член-фунцкия, която:
* се извиква само веднъж, **при изтриването на обекта**
* няма тип на връщане
* няма параметри
* има същото име като класа с ~ отпред
* не може да се overload-ва - **има само един деструктор**
* зачиства ресурсите
* ***деструкторите се викат в обратен ред на реда на конструкторите***. Причината:
```c++
class A {
public:
	A() {...}
};

class B {
	A a;
public:
	B() {...} // не казваме нищо за A, ще се извика default-ен конструктор
};

class C {
	A a;
	B b;
public:
	C() {} // не казваме нищо за A и B, ще се извика default-ен конструктор
};

int main() {
	C* ptr = new C();
	return 0;
}
```

Така подредени обектите, в програмния стек ще имаме нещо такова:

![](/recap/resources/stack.png)

Стъпка по стъпка:
1. Създаваме `A`, което е вътре в `C`
2. Създаваме `B`, което е вътре в `C`
   1. първо създаваме `A`, което е вътре в `B`
   2. създаваме каквото останало има в `B`
3. Най-накрая завършваме и създаването на `C`

Съответно, като дойде време за извикване на деструкторите, тоест *да освободим ресурсите*, значи да освободим програмния стек. Както се вижда на картинката, най-отгоре е `C`, после `B` и най-накрая две `A`-та -> точно обратния ред на създаване

## Rule of Three/Five
Вече разбрахме как създаваме и изтриваме обект от стъпките в *жизнения цикъл на обект*. Там обаче имаме и работа със съответния обект. В процеса на работа обаче много често се случва да копираме даден обект, например:

```c++
class A {...}

void f(A obj) {} //подаваме го по не-референция -> правим му копие
```

Копирането се покрива от два механизъма: ***копиращ конструктор и oprator= (assignment operator)***
* както може да се досетите от името, копиращия конструктор създава нов обект (*затова е конструктор*), който е копие на друг, вече съществуващ
  * извършва  операциите:
    * копиране на данните от оригиналния обект
  * `A(const A& other)`

* за оператори ще говорим по-късно, засега важното е, че използваме *operator=*, когато **имаме съществуващ обект, със свое съдържание, и искаме да го направим копие на друг обект** - ключовото е, че обекта съществува, а не го създаваме
  * извършва  операциите:
    * изтриване на съществуващите данни
    * копиране на данните от оригиналния обект
  * `A& operator=(const A& other)` - връщаме референция, за да може да chain-ваме няколко операции по присвояване на стойност
    * *a = b = c = d*
  
И двете биват автоматично генерирани от компилатора, ако не го направим ние самите

### Как работят
```c++
class A {
    int i;
    char c;
}

class B {
    int* arr;
    int n;
}

int main() {
    A a1;
    A a2(a1); // така се извиква копиращ констр.;
    // ефективно сме направили a2.i = a1.i и a2.c = a1.c
}
```

Какво обаче ще стане, ако искаме да направим копие на `B`? Както виждате от примера с `A`, компилатора просто вика operator= на всяка член-данна на самия клас. Както знаете от УП обаче, когато приравним два указателя, ние просто ги караме да сочат към едно и също място. Получава се:

![](/recap/resources/shallow_copy.png)

Това е т.нар. **shallow copy** - не сме направили истинско копие на паметта, само сме накарали указателите да сочат към едно и също място. Така, *ако изтрием първия обект, трием това парче памет, към което сочи и другото копие - имаме **memory leak***

Целим обратното, да имаме истинско, отделно копие на паметта, тоест **deep copy**

![](/recap/resources/deep_copy.png)

**Решението е просто ние сами да си разпишем копиращ констр. и operator=**

Така, *конструктора, копиращия констр., operator= и деструктора* образуват ***Голяма четворка/Rule of Three*** (в английската литература не включват нормалния конструктор, затова са само three)

От УП знаете, че имаме `lvalue` - най-общо казано *именувани променливи, които имат адрес в паметта* - и `rvalue` променливи - стойности, без място в паметта. Допълнително те се делят на `prvalue` - най-често литерали - и `xvalue` - обекти към края на жизнения си цикъл. Обикновено на нас самите не ни се налага да правим разграничението, компилатора го прави, но все пак е хубаво да се знае, че го има.

***Защо е важно?***

Ако сте обърнали внимание, *копиращия конст. и operator=* приемат `const A& other` (ако класът ни е `A`) - това си е чисто `lvalue`. Но както стана ясно, в C++ има още един отделен тип данни - `rvalue`. Можем ли по такъв начин да направим *копиращия конст. и operator=*, така че да покрият целия ни апарат от данни?

Ами точно това е смисъла от move семантиките - да ни позволят да можем да копираме и `rvalue` обекти. Защо тогава казахме, че е *оптимизация* на процеса по копиране - ами заради начина, по който го реализираме.

Ако `rvalue` обектите са временни, то те скоро ще бъдат изтрити след като ги копираме. Получава се:
1. имаме rvalue обект
2. създаваме му deep copy, което понякога се оказва тежка операция

3. изтриваме оригиналния обект

Така сме извършили deep copy за нещо, което е можело и да не копираме, защото вече не съществува. *Move операциите* просто "крадат" паметта на `rvalue` обекта, оставят го в състояние, в което не може да навреди на данните и така си спестяваме ненужното копиране.

На картника:

![](/recap/resources/move_example.png)

Така получаваме
* **move копиращ конст.** - `A(A&& other)`
* **move oprator=** - `A& operator=(A&& other)`

Така, ***Rule of Three** + **move семантики** = **Rule of Five***

### Неща, на които да обърнете внимание
* вижте помощните функции `copyFrom`, `moveFrom`, `free`

* подобно на &, && също е вид референция, просто към `rvalue` обект, съответно и това е типа обект, който приемат `moveFrom`, **move operator=** и **move копиращ констр.**

* компилатора ще се опита и най-вероятно ще успее да направи move операциите, но все пак ако не успее, **ще използва нормалните копиращ констр. и operator=**

* `std::move` - помощна функция, която превръща `lvalue` в `rvlaue` - ***обърнете ѝ много специално внимание***

## Предифиниране на оператори (operator overloading)
От **Rule of Three/Five** сигурно ви е направило впечатление, че синтаксиса на *assignment operator* е малко особен - винаги пишем думата `operator`. Ами това се дължи на факта, че C++ поддържа механизъм, който ни дава да предефинираме оператори.

Доста съкратено за операторите, те представляват операции между два обекта, които могат да ни върнат резултат. Имаме
* унарни (с един аргумент) - ++, --, ...
* бинарни (с два аргумента) - +, -, %, ...
* тернарни (с три аргумента) - само ?:

Както знаете от УП, можем да **overload-нем функция** - т.е. спрямо различни подадени параметри един и същ метод да прави различни неща.

Предефинирането на оператори ни позволява да дефинираме поведението на оператор, в зависимост от типа/обекта, върху който се прилага - **нашия клас** (напр. с operator=, задаваме поведението по правилно копиране на нашите класове)

Ако предефинираме оператор като член-функция на клас, то първия параметър е указателя `this`

***Може да се предефинират само съществуващи оператори***

Характеристики на операторите:
* приоритет
* асоциативност
* позиция

Като предефинираме оператор трябва да спазваме тези характеристики

### Приятелски функции
* декларират се със запазената дума **friend**

* приятелските функции/класове имат достъп до всички компоненти на класа
*  те не се наследяват и не са транзитивни (`A` е приятел на `B` и `B` е приятел на `C`, но `A` не е непременно приятел на `C`)
*  декларират се в класа, но реално не са член-функции
*  някои оператори като `operator<<` и `operator>>` задължително са такива  

### operator<=>
* една от новостите на езика
* дава ни начин за въвеждане на естествена наредба - вместо да пишем всички сравнения <, >, <=, =>, ==, !=, можем да напишем само това + operator==

* примитивните член-данни имат вграден такъв оператор - ако ние предефинираме такъв за нашия клас, то той ще се опре на вече съществуващите

* аналог. на *compareTo* в други езици като Java

* в много прости класове/сравнения може да работи и без, но като правило **operator<=> върви в комплект с operator== (т.е. предефинираме и двата)**

```c++
class A {
    int i;
    double d;
    char c;
}

int main() {
    A a1;
    A a2;

    a1 <=> a2; // ще сравни първо a1.i <=> a2.i, ако са равни - a1.d <=> a2.d и накрая ако и те са равни - a1.c <=> a2.c
    // движи се по член данните една по една докато ги изчерпи или докато достигне неравенство
}
```

## Бележка под линия/други важни неща
* **mutable**
  * дава ни възможност да променим константни член-данни
  * ползва се само в много краен случай, понеже нарушава const correctness

* когато имаме move операции
  ```c++
  class A {
    moveFrom(A&& other) {...}

    A(A&& other) {
        moveFrom(std::move(other));
    }
  }
  ```
  * първо, понеже пренасочваме накъде да сочат указателите, т.е. променяме обекта, не го подаваме като константа
  
  * въпреки че сме подали `rvalue` обект на конструктора, вътре в неговия scope той все пак трявба да се "закачи" към някаква променлива, че да можем да го използваме в операциите като именувана променлива - *в някакъв смисъл вътре в scope-а го третираме като `lvalue`*. Затова го подаваме с `std::move` на `moveFrom`
